# PRD-260826：数据字段加密与隐私保护

## 1. 背景

Porsche 后端将保存用户身份信息、对话内容、审计信息和访问控制信息。当前密码与 Gateway Token 已采用不可逆哈希，但手机号、实名信息、会话内容和部分审计字段仍以明文持久化。需要建立统一的字段级保护策略，降低数据库泄露、备份泄露和越权查询造成的隐私风险。

## 2. 目标

- 对高敏感、可还原的个人信息和内容数据采用应用层加密。
- 对仅需比对、不需还原的数据采用带密钥的 HMAC，而非普通哈希。
- 保持密码、Gateway Token 等凭据不存储明文。
- 密钥不存入 MySQL、不写入日志，并支持后续轮换。

## 3. 已确认的字段策略

| 字段/数据 | 当前处理 | 目标策略 |
| --- | --- | --- |
| `users.password_hash` | bcrypt 哈希 | 保持不可逆哈希，不加密、不保存明文。 |
| `gateway_api_tokens.token_hash` | SHA-256 哈希 | 保持只存摘要；后续评估升级为 HMAC-SHA-256，不保存完整 Token。 |
| `users.id_card_hash` | 普通 SHA-256 | 改为使用独立密钥的 HMAC-SHA-256；不保存身份证原文。 |
| `users.phone` | 明文、唯一索引 | 改为密文 + HMAC 盲索引，以支持登录和唯一性校验。 |
| `users.real_name` | 明文 | 应用层加密保存。 |
| `conversations.title`、`messages.content` | 明文 | 应用层加密保存，覆盖用户 Prompt 与模型回复。 |
| `audit_logs.detail` | 明文 JSON | 先做字段白名单与脱敏；确有保存必要的敏感明细整体加密。 |
| `audit_logs.ip` | 明文 IP | 根据审计与风控需求，在精确加密保存、HMAC 或网段截断之间确定策略。 |
| 未来发票资料 | 当前未持久化具体资料 | 若保存抬头、税号、地址、开户信息等，必须应用层加密。 |

## 4. 非功能安全要求

- 使用经认证加密（如 AES-256-GCM）或由密钥管理服务托管的信封加密；每条密文应携带所需 nonce/认证标签与密钥版本。
- 加密主密钥、HMAC 密钥、JWT 密钥和上游 API Key 必须位于 KMS/Secret 管理或部署环境变量，不能写入数据库、代码库、日志或审计详情。
- MySQL 连接使用 TLS；磁盘/卷、备份与导出文件应启用静态加密和最小权限访问。
- DTO、管理接口、错误响应和日志不得返回或记录明文 Token、Prompt、身份证、完整手机号或解密后的审计详情，除非经明确授权的最小必要场景。
- 新增字段、迁移和写路径必须继续遵守 `docs/conventions/database-standards.md` 的 guid、审计字段、逻辑删除和 MySQL 8 约束。

## 5. 待统一决策

以下问题将在下一轮评审后补全：

1. 本 PRD 的主要读者是否同时覆盖后端开发、运维和安全人员。
2. 首期范围是否确认包含手机号、实名、会话标题/消息、审计详情/IP 与身份证 HMAC。
3. 是否只面向新环境，还是需要迁移历史明文数据。
4. 密钥提供方是否使用云 KMS；若未确定，是否先定义可替换的密钥提供方接口。
5. 手机号精确登录/查询是否采用“密文 + HMAC 盲索引”方案。
6. 是否需要对加密后的历史会话支持关键词搜索；若需要，必须另行确定检索与泄露边界。
7. 实施优先级是否为：身份证 HMAC → 手机号密文与盲索引 → 会话内容加密 → 审计脱敏与加密。

## 6. 初步验收标准

- 数据库中不存在手机号、实名、会话标题、会话内容或身份证号的新增明文持久化字段。
- 密码和 Gateway Token 仍无法从数据库还原；完整 Gateway Token 只在创建时一次性返回。
- 身份证比对不再使用无密钥 SHA-256。
- 加密/解密失败不回显明文或密钥，且有安全的审计与告警路径。
- 密钥轮换后，可按照密钥版本读取既有数据并逐步重加密。

## 7. 本期边界

本 PRD 仅记录需求和待决策项；不授权当前修改数据库、迁移、加密实现、密钥服务或生产配置。
