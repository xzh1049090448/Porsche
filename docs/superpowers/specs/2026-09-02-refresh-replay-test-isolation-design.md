# Refresh 重放与集成测试隔离修复设计

## 目标与授权

用户已批准修复 Refresh 空指针及测试隔离。本文明确实施边界，待书面设计确认后执行。
仅在 `fix/open-issue-resolution` 工作树修改和本地提交，不推送、合并、关闭 Issue、访问生产服务或部署。
不修改生产 schema、迁移、认证 API、Redis 键格式、重放窗口或安全策略。

## 已确认根因

1. `SessionService.Refresh` 的过期重放分支先写 Redis 否决栅栏，再提交 MySQL 会话撤销和审计；成功时 `rotated` 仍为 nil，事务外却读取 `rotated.Session.RefreshHMAC`，产生 panic。上一轮单独运行真实 MySQL/Redis 用例已复现。
2. Root 引导测试共享数据库，前面测试留下的 Root 改变了“尚无 Root”的前提，甚至可能让墓碑测试因其他 Root 而误通过。
3. 密码审计故障测试添加全表 CHECK，其他用户已存在的合法事件导致约束本身无法安装。
4. 固定注册用户名、Redis 限流 IP 和轮换 SID 会在重复执行中复用状态。

## 方案比较与选择

- **推荐：最小业务修复和针对性测试隔离。** 只有 Root 引导用例新建独立临时库；其他测试保留共享的显式测试库，但采用唯一标识及用户级故障约束。无须更改生产 Redis 接口。
- **全部用例独立 MySQL/Redis 实例。** 隔离最强，但大量容器启动和迁移会延长测试，并引入 Docker 作为每个用例的运行依赖。每例仅独立 MySQL 库还不充分：内部用户 ID 重复会碰撞 Redis 签发计数。
- **每轮清空共享库。** 不采用：破坏既有测试数据，不能消除同轮的顺序依赖，也不适合并发执行。

## Refresh 修复

在事务成功返回之后、发布轮换结果之前检查 `rotated == nil`，此时返回现有未认证错误（401）且不返回令牌。
不能在成功撤销的事务回调里直接返回认证错误，否则 GORM 会回滚会话撤销和审计。
已有 MySQL/Redis 错误继续按原路径返回，不吞掉错误、不伪造撤销成功。

强化真实集成回归：以受控时钟越过重放窗口，断言 nil 结果、401、MySQL revoked_at、精确一次 replay-revoked 审计和 Redis 否决栅栏；再次使用旧令牌或轮换后的令牌都被拒绝。
保留窗口内并发返回同一结果和 A→B→C 不回退的测试。增加审计写入失败回归，证明 MySQL 回滚而 Redis 仍 fail-closed。

## 测试隔离

### Root 引导

仅两项 Root 引导测试使用 `_test.go` 中的新辅助函数：验证显式 `TEST_DATABASE_URL` 的专用测试库条件后，连接该测试 MySQL，并创建随机命名、以 `_test` 结尾的新库。
使用非 `IF NOT EXISTS` 的 CREATE，失败即停止，不能接管既有库；只在创建成功后注册该精确库名的清理。
在新库运行现有显式迁移，测试结束关闭连接并删除本次创建的库；不删共享测试库、不改已有用户、不读 `.env`。
只有本地临时 MySQL 容器的测试账号需要 CREATE/DROP 权限，不要求生产账号具备此权限。
增加隔离验证：不同 fixture 看不到彼此 Root，清理不影响父测试库。墓碑用例明确验证库中唯一 Root 为该墓碑。

### 其他 MySQL 用例

密码审计故障 CHECK 限定到本用例的 `user_id` 和目标 `event_type`，保留真实 MySQL 约束失败；清理只移除本次创建的唯一约束名。
固定注册用户名改用现有完整 Snowflake 短前缀规则，仍断言 trim、20 字符上限和软删后永久占用；HTTP 流的注册及多次登录使用同一动态用户名。

### Redis 用例

限流用例使用每次执行唯一的测试账户与 IP 标识，轮换存储用例使用新生成的 SID。
不新增生产用的测试开关或可变前缀，不调用 FLUSHDB/FLUSHALL，不改变 Lua/加密协议，不跳过真实 Redis。
全套测试使用本任务新建的 disposable Redis；保留同一实例进行重复运行，验证状态不会干扰下一轮。
