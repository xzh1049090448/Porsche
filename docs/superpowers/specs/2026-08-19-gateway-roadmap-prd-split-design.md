# 网关后续阶段 PRD 拆分设计

## 目标

将原始企业级 AI 网关 PRD 中尚未实现的能力拆成五份可独立评审、排期和验收的阶段 PRD，避免在单一需求中混合渠道可靠性、计量治理、资源授权和财务结算。

## 拆分顺序

1. 多渠道路由与 SSE 联调
2. 请求用量审计
3. 配额与限流
4. 组织与项目
5. 账务与结算

## 依赖原则

- 阶段 1 输出可识别的实际渠道和一次请求的路由结果，供计量归因使用。
- 阶段 2 输出幂等的请求与用量记录，供配额判断和后续结算使用。
- 阶段 3 基于已审计的调用量执行实时控制，不承担财务结算。
- 阶段 4 建立组织、成员、项目和资源归属，供团队级额度和账务归集使用。
- 阶段 5 只在前四阶段的渠道成本、用量、额度和归属可追踪后实现。

## 每份 PRD 的固定结构

每份文件必须包含目标、前置依赖、用户故事、功能范围、核心规则、验收标准、非目标、风险和下一阶段交付物。每项验收标准应可通过自动化测试、接口测试或预发布环境验证，而不是仅描述实现代码。

## 边界

- 不重新定义已完成的 Gateway Token、模型 ACL、IP 白名单、撤销和过期能力。
- 不把前端展示、后端实现和部署细节混成一个无边界需求；每份 PRD 仅列出必要的契约和可观测性要求。
- 真实上游联调和生产数据验证必须使用合法授权的服务与脱敏数据。
