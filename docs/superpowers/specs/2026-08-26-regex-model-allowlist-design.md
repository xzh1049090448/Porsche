# 全局模型正则白名单设计

## 目标

允许通过 `JIEKOU_ALLOWED_MODELS` 的显式正则项展示和调用一组上游模型；例如 `re:^.+$` 允许所有通过 Porsche 安全模型 ID 校验的上游目录模型。

## 配置契约

`JIEKOU_ALLOWED_MODELS` 仍是逗号分隔列表，每个非空项只有两种含义：

- 普通文本：精确模型 ID，例如 `zai-org/glm-5.1`。
- `re:` 前缀：Go RE2 正则，例如 `re:^zai-org/.+$`；`re:^.+$` 表示全部安全模型 ID。

正则从 `re:` 之后的完整文本开始匹配。服务在启动加载配置时编译每个正则：空表达式、编译失败或全部项为空都使启动失败。普通文本仍使用现有安全模型 ID 校验；正则本身不用于构造 URL。

## 授权边界

只有全局白牌 allowlist 支持正则。用户 `allowed_models` 与 Gateway Token `allowed_models` 保持精确字符串 ACL：

- 为空时，主体可使用全局 allowlist 匹配到的全部目录模型；
- 非空时，模型必须同时匹配全局精确/正则 allowlist，且精确出现在该主体 ACL 内。

因此 `re:^.+$` 不会让带有限制 ACL 的用户或 Token 自动获得全部模型权限。

## 运行时行为

上游目录仍先过滤不安全的模型 ID，再执行全局 allowlist 匹配。目录、详情、普通 Chat、SSE、Compare 与管理员健康检查均复用同一 `WhiteLabelService.permitted` 判定。匹配成功的模型 ID 原样保留，用于缓存、ACL、审计、计费与通过 `url.PathEscape` 构造的上游详情路径；不新增数据库表、迁移或模型映射。

## 错误与可观测性

- 非法配置必须 fail-closed，并仅返回“无效白牌模型配置”类错误，不回显 API Key。
- 对外模型不存在、ACL 拒绝或目录不可用的现有统一错误契约不改变。
- `/admin/status` 的 `configured_models` 继续表示配置项数量（精确项与正则项之和），不将正则展开成不稳定的上游模型数量。

## 验收

1. `re:^.+$` 令所有安全上游目录模型通过全局 allowlist；精确配置保持既有行为。
2. `re:^zai-org/.+$` 只允许对应组织前缀的安全模型。
3. 无效、空或正则不合法的配置在启动前失败，且不泄露密钥。
4. 用户/Token 的非空精确 ACL 仍可拒绝正则全局允许的模型，且拒绝时不访问上游详情。
5. 后端单测、`go test ./...`、`go vet ./...` 通过；部署环境以 `re:^.+$` 完成真实目录、详情、Chat 与 SSE 冒烟后再更新 Issue #2 证据。
